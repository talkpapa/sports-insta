# @sportsnewsstation — 무인 자동화 파이프라인

스포츠 **데이터**를 받아 **카드 그림**으로 찍고, **캡션**을 지어, **인스타에 자동으로 올립니다.**
사람이 손대지 않아도 **하루 3개**가 시간을 나눠 나갑니다.
(안정되면 6개로 올릴 수 있습니다 — 아래 4단계 뒤 설명)

> 기존 `C:\TIM\Claude\인스타` (클락톡 계정) 와는 **완전히 별개**입니다.
> 파일도, 토큰도, 저장소도 섞이지 않습니다.

---

## 왜 사진을 쓰지 않는가

이 파이프라인은 **사진을 한 장도 쓰지 않습니다.** 일부러 그렇게 지었습니다.

스포츠 사진은 거의 전부 통신사(AP·게티·연합) 소유입니다. 기사 문장도 남의 글입니다.
사람이 매번 확인한다면 조심해서 쓸 수도 있지만, **무인으로 도는 계정은 그럴 사람이 없습니다.**
하루 3개라도 한 달에 90개입니다. 그중 하나만 잘못돼도 계정이 위험하고,
인스타 API 로는 **삭제도 안 됩니다.**

그래서 **점수·순위·일정만** 받습니다. 숫자는 사실이라 저작권이 없습니다.
카드는 원장님 디자인으로 직접 그립니다.

덤으로, 순위표 같은 **정보성 카드가 저장(save)이 훨씬 잘 눌립니다.**
저장과 공유는 인스타가 노출을 밀어주는 가장 큰 신호입니다.

## 하루가 어떻게 도는가

```
아침 9시                        12:30       18:30       21:30
──────────────                  ────────────────────────────────────────
데이터 3개치 받기                 슬롯 하나씩 게시
   ↓                              ↓
카드 그리기 (슬롯 01~03)          게시 전 검사 → 통과해야 올라감
   ↓                              ↓
캡션 짓기                        나간 슬롯은 _done 으로
   ↓
커밋 → Pages 에 카드 게시
```

**아침 9시에 만드는 데는 이유가 있습니다.**
"어제 경기 결과"를 받는데, 데이터 제공처는 **UTC 날짜**로 경기를 묶습니다.
한국시간 아침 9시가 정확히 UTC 자정이라, 이때가 되어야 어제가 완전히 끝납니다.
더 이르게 잡으면 유럽 밤경기가 아직 진행 중이라 결과가 반쪽만 옵니다.

**게시를 12시 반부터 시작하는 이유**는 Pages 반영 때문입니다.
커밋 후 실제로 주소가 열리기까지 몇 분 걸립니다. 두 시간 여유를 뒀습니다.

**한 번에 하나만 올립니다.** 여러 개를 한꺼번에 쏟으면 서로의 도달을 깎아먹고,
새 계정이 그러면 스팸으로 읽혀 노출이 눌립니다.

## 슬롯 구조 — 하나가 실패해도 나머지는 나갑니다

하루치가 파일 3개로 쪼개져 있습니다.

```
queue/2026-08-20/01.md  02.md  03.md
                  ↓ 나가면
queue/_done/2026-08-20/01.md
```

나간 것만 `_done` 으로 옮겨지므로, **남아 있는 것 중 첫 번째가 언제나 다음에 나갈 것**입니다.
3번째에서 실패해도 그 슬롯은 그대로 남아 다음 시각에 이어서 나갑니다. 건너뛰지 않습니다.
그날 몫을 다 채우면 남은 실행은 스스로 멈춥니다.

---

## 게시 전에 무엇을 검사하는가

사람이 안 보고 나가므로, **조금이라도 이상하면 올리지 않습니다.**
한 개 거르는 것이 이상한 게시물이 영구히 남는 것보다 낫습니다.

| 검사 | 걸리면 |
|---|---|
| 오늘 몫(3개)을 이미 채웠는가 | 중단 |
| 같은 슬롯을 두 번 올리려는가 | 중단 |
| 직전 게시와 1.5시간 이상 떨어졌는가 | 중단 (연달아 나가는 사고 방지) |
| 캡션이 2,200자 안인가 | 중단 |
| 해시태그가 30개 안인가 | 중단 |
| 캡션에 `undefined` · `NaN` 이 박혀 있는가 | **중단** — 데이터가 비면 문장에 그대로 찍힙니다 |
| 카드 주소가 실제로 열리는가 | 중단 (Pages 반영이 늦으면 여기서 걸립니다) |
| 그림 비율이 0.80 ~ 1.91 인가 | 중단 (벗어나면 인스타가 거부합니다) |
| 그림이 8MB 이하인가 | 중단 |
| 자료가 오늘·어제 것인가 | 중단 (묵은 데이터 방지) |

## 처음 한 번만 하실 일

### 1단계 — GitHub 저장소를 만들고 Pages 를 켭니다

1. GitHub 에서 새 저장소를 만드십시오 (예: `sports-insta`). **Public** 이어야 Pages 가 공짜입니다.
2. 이 폴더를 그 저장소에 올리십시오.
3. 저장소 **Settings → Pages** → Source `Deploy from a branch`,
   Branch `main` / `/docs` 로 저장하십시오.
4. `config.json` 의 `hosting.pagesBase` 에 나온 주소를 넣으십시오.

```json
"hosting": { "pagesBase": "https://내아이디.github.io/sports-insta" }
```

> 이 주소가 비어 있으면 `build` 가 **시작도 하지 않고** 멈춥니다.
> 카드를 다 그린 뒤에 주소가 없다고 멈추면 헛일이기 때문입니다.

### 2단계 — football-data 키를 받습니다 ⭐

무료입니다. 이메일 등록만 하면 됩니다.

1. [football-data.org/client/register](https://www.football-data.org/client/register) 에서 키를 받으십시오.
2. 저장소 **Settings → Secrets and variables → Actions** 에 `FOOTBALL_DATA_KEY` 로 넣으십시오.

> **왜 필수인가:** 기본으로 쓸 수 있는 무료 TheSportsDB 는 목록을 3~5건으로 **잘라서** 줍니다.
> 실제로 시험해 보니 "어제 라리가 경기"를 1건만 주더군요. 그걸로는 하루 3개도 빠듯하고,
> 채우더라도 순위표만 세 장 나가는 부실한 계정이 됩니다.
> football-data 는 리그 10개의 전체 데이터를 줍니다.

### 3단계 — 인스타 토큰을 발급받습니다 ⭐

**어느 계정에 올라가는지는 오직 이 토큰이 정합니다.** config 에 적은 아이디는 카드에 찍히는 글자일 뿐입니다.

토큰 발급은 **원장님이 직접** 하셔야 합니다 (비밀번호를 넣는 일이라 제가 대신 할 수 없습니다).

1. `@sportsnewsstation` 을 **프로페셔널(비즈니스 또는 크리에이터)** 로 바꾸십시오.
   인스타 앱 → 설정 → 계정 유형. 개인 계정은 API 가 아예 안 됩니다.
2. [developers.facebook.com](https://developers.facebook.com) → **내 앱** → 앱 만들기
   → 용도 **기타**, 유형 **비즈니스**.
3. 앱에 **Instagram** 제품을 추가하고 **API setup with Instagram login** 을 고르십시오.
4. 계정을 연결한 뒤 **장기 액세스 토큰(long-lived access token)** 을 생성하십시오.
5. 저장소 시크릿에 `IG_TOKEN` 으로 넣으십시오.

> 토큰은 **60일**이면 죽습니다. `토큰 연장` 워크플로가 매주 월요일에 새 토큰을 뽑아
> 로그에 남깁니다. **그 토큰을 `IG_TOKEN` 시크릿에 다시 붙여넣으셔야** 합니다.
> 서버는 자기 시크릿을 스스로 못 바꿉니다. 만료 14일 전부터 크게 경고가 뜹니다.

### 4단계 — 손으로 한 번 돌려 확인합니다

저장소 **Actions** 탭에서 `카드 만들기` → **Run workflow** 를 누르십시오.
커밋이 생기고 몇 분 뒤 `https://내아이디.github.io/sports-insta` 에서 카드가 보이면 성공입니다.
그다음 `게시` 를 손으로 한 번 돌려 첫 게시물을 확인하십시오.

## 무엇을 고치면 무엇이 바뀌나

전부 `config.json` 한 파일에 있습니다.

| 고치는 곳 | 바뀌는 것 |
|---|---|
| `account.handle` | 카드 왼쪽 아래 계정명 |
| `account.brand` | Pages 보관함 제목 |
| `leagues` | 다루는 리그. **많을수록 하루치 소재가 넉넉합니다** |
| `publish.perDay` | 하루 몇 개 (지금 3). 올리실 때는 `post.yml` 의 cron 주석도 푸십시오 |
| `publish.maxSlides` | 캐러셀 최대 장수 (인스타 한도 10장) |
| `publish.minGapHours` | 직전 게시와 최소 간격. 슬롯 간격(2~2.5시간)보다 작아야 합니다 |
| `hashtags` | `공통` + 리그별이 합쳐집니다 |

**게시 시각**은 `.github/workflows/post.yml` 의 `cron` 입니다.
cron 은 **UTC** 라 한국시간에서 9시간을 뺀 값입니다 (21:00 → `0 12 * * *`).

**새 리그**를 넣으실 때 football-data 무료 키로 되는 코드:
`PL`(EPL) `PD`(라리가) `SA`(세리에A) `BL1`(분데스리가) `FL1`(리그앙) `CL`(챔스)
`DED`(에레디비지) `PPL`(포르투갈) `BSA`(브라질) `ELC`(챔피언십).

**구단 한글 이름**은 `scripts/lib/teams-ko.js` 에 있습니다.
없는 구단은 영문 그대로 나갑니다(틀린 한글보다 낫습니다). 한 줄씩 더하시면 됩니다.

## 손으로 돌려보실 때

```bash
npm install
npm run fonts
```

| 명령 | 하는 일 |
|---|---|
| `node scripts/render.js` | 가짜 데이터로 `_demo/` 에 카드를 그려 봅니다 — **디자인 확인용** |
| `node scripts/collect.js` | 오늘 쓸 소재가 잡히는지 봅니다 |
| `node scripts/collect.js --all` | 리그별로 무엇이 있는지 전부 봅니다 |
| `node scripts/build.js --dry` | 만들어 보되 **파일은 쓰지 않습니다** |
| `node scripts/build.js` | 실제로 오늘 슬롯을 만듭니다 |
| `node scripts/verify.js` | 다음 슬롯을 검사만 해 봅니다 |
| `node scripts/ig.js status` | 계정·오늘 진행 상황·토큰 상태 |
| `node scripts/ig.js queue` | **다음 슬롯을 실제로 게시합니다** (되돌릴 수 없습니다) |

로컬에서 쓰시려면 `.env.example` 을 `.env` 로 복사해 값을 채우십시오.
`.env` 는 git 에 올라가지 않습니다.

## 폴더 구조

```
스포츠인스타/
  config.json              ← 여기만 고치면 거의 다 됩니다
  scripts/
    collect.js               데이터 받기 (제공처 2곳 지원)
    render.js                카드 그리기 (브라우저 없이)
    caption.js               캡션 짓기
    build.js                 위 셋을 묶어 하루치 완성
    verify.js                게시 전 검사
    ig.js                    실제 게시 · 토큰 연장
    setup-fonts.js           서체 내려받기
    lib/
      util.js                설정·날짜·상태·네트워크
      queue.js               슬롯 읽기 (verify 와 ig 가 함께 씁니다)
      teams-ko.js            구단 이름 한글 표기
      josa.js                조사 교정 (…이/가, …와/과)
  docs/                    ← GitHub Pages. 카드가 여기 쌓입니다
    cards/2026-08-20/01/01.png
    index.html               만든 카드 보관함
  queue/2026-08-20/01.md ~ 03.md
  queue/_done/               나간 것
  state.json               게시 이력 · 리그 순번 · 토큰 만료일
  .github/workflows/
    build.yml                아침 9시 — 하루치 만들기
    post.yml                 하루 3번 — 하나씩 올리기
    refresh.yml              월요일 — 토큰 연장
```

`assets/fonts/` 와 `node_modules/` 는 git 에 넣지 않습니다.
서체는 4MB 라 저장소가 무거워지고, 쓸 때마다 `npm run fonts` 가 알아서 받습니다.

## 알아두실 한계

- **소재가 3개 안 나오는 날이 있습니다.** 리그가 쉬는 날(A매치 기간, 시즌 사이)에는
  결과도 일정도 없어 순위표만 남습니다. 그런 날은 있는 만큼만 나갑니다 — 억지로 채우지 않습니다.
  더 채우고 싶으시면 `config.json` 에 리그를 더 넣으십시오.
- **토큰 연장은 반쯤만 자동입니다.** 서버가 자기 시크릿을 못 바꿔서, 60일마다
  한 번은 손으로 붙여넣으셔야 합니다.
- **댓글 응답은 없습니다.** 남의 계정 자동 좋아요·팔로우도 없습니다 —
  인스타 정책 위반이라 계정이 정지됩니다. 일부러 넣지 않았습니다.
- **처음엔 하루 3개로 시작합니다.** 인스타 API 한도(24시간 50개) 안이라 6개도 기술적으로는
  문제없지만, 갓 만든 계정이 갑자기 많이 올리면 노출이 눌릴 수 있습니다.

## 나중에 하루 6개로 올리실 때

두 군데만 고치면 됩니다. 2~3주 돌려 보시고 반응이 괜찮으면 올리십시오.

1. `config.json` → `publish.perDay` 를 `3` 에서 `6` 으로
2. `.github/workflows/post.yml` → 주석 처리된 cron 세 줄의 `# ` 를 지우기
   (11:00 · 16:00 · 23:00 이 살아나 하루 6번이 됩니다)

반대로 줄이실 때는 `perDay` 만 낮추면 됩니다 — 남는 시각은 알아서 넘어갑니다.
